# Frank Trading + trade-skills 调研 — 给 option-wizard 重写 prompt 用

**抓取方式**：`opencli web read --url ...`（Chromium bridge，带登录态）一次成功，4 篇全文无 paywall 截断，落盘在
`scratchpad/web-articles/08_{10,17,24,31}_2026_复盘与展望/`。`opencli substack publication` 用来枚举归档。
Playwright MCP / WebFetch 未使用。**重要事实纠正**：Frank 的 note 是**周更**（每周一早发，中英双版），不是日更 —
"daily briefing" 的类比要打折扣，但结构可以按日拆。

## 2. 他的推理流水线（可让 agent 照做的编号流程）

1. **先 mark-to-market 上一次的判断**，逐笔说兑现或止损，不美化（LLY 亏了就写亏了）。
2. **从指数周表现里挑"最反常的那一件事"**，而不是罗列涨跌 —— 08/31 是 "momentum 是最弱因子之一，尽管 NVDA 给出史诗级指引"。
3. **用"利好落地反而暴跌"作为定价权耗尽的判据**（MRVL beat+raise 跌 10.3%；SMH 单日 -3.47%）。催化剂不再产生正面价格反应 = 边际买家用完。
4. **利率是第一因**：先定 2Y/10Y/2s10s + 加息概率，再推谁最受伤（对现金流久期排序：XBI 无现金流超长久期 > IWM 浮息债务占比最高 > CRWV 靠发中短债买 GPU）。
5. **把政策讲话剥成 reaction function**，不猜下一步：Warsh 三层意思 → 翻译成"经济很好、通胀不降、保留所有选项"。
6. **对下一个事件写 A/B/C/D 情景 + 传导顺序**，并声明 base case 和**选它的理由**（"我偏向 B 的原因在于 FCI：NFCI -0.53 还在宽松区"）。
7. **板块分化归因到"预期门槛"而非"景气度"**：IGV +5.9% / SOXX -2.2%，"两边交易的是不同的预期门槛，而非 AI 景气度突然从硬件搬到软件"。
8. **单名深挖只挖结构性资产负债表问题**，不挖 EPS（NVDA 的 $530B 表外承诺拆成三层担保、wrong-way risk、GPU 无 stationary residual-value distribution）。
9. **GEX/DEX 给出当周价格地图**：一个"状态切换区"、上方第一压力、中枢带、下方两层支撑、结构性防线。方向不由 GEX 决定，GEX 只给触发/失效价位。
10. **catalyst 预案写成"什么组合算证实"**：非农那段——"收益率回落+股票上涨 = 政策压力缓解；收益率回落+股票下跌 = 增长担忧压过利率利好，我会下调风险敞口"。
11. **落到编号仓位**，每条带方向 + 触发 + 加仓线 + 止损 + 目标（08/24 的 ZN/UB 是最完整的样本）。

**语言风格**：中文口语 + 英文术语混排；**粗体只给结论句**；数字永远带单位和变化量（"2Y 全周 +10bps 到 4.34% 创周期新高"）；
从不说"可能会涨"，只说"站上 7705 是结构修复，跌破 7690 是短线转弱"。全文 3–5k 中文字，含 8–10 张截图。
表达信心用**"我的 base case"/"我最核心的宏观判断"/"我偏向这个情景的原因在于…"**，反向风险单独成段（"这是我们做空之前必须承认的反向风险"）。

## 4. trade-skills（github.com/himself65/trade-skills）值得抄的部分

结构：一个 Claude Code plugin marketplace，只有一个 skill `plugins/trade/skills/trade/`。
`SKILL.md`（187 行，always-on 规则）+ `references/` 懒加载：6 个 framework（macro / gamma / price-action /
parent-order-flow / overnight-futures / strategies）、**36 条 pitfalls**（一文件一条，带 OKF frontmatter + index 的
"按交易类型查"反查表）、ticker 案例、`log.md`。知识分 L1 公共规则 / L2 私人判断 / L3 原始语料三层，**L2 每次
session 全扫、有 size budget，L3 永不自动加载** —— 这套分层直接可以搬到 option-wizard 的 prompt 预算管理上。

**值得借**：① 三轴结构选择（direction / vega / **asymmetry**）；② "输出概率+价位，不输出方向预测"的 GEX 用法；
③ 七问 gate；④ 入场区与止损的几何检查；⑤ pitfalls 的按情境反查索引（agent 可按当前 situation 精确加载 1–3 条，而不是灌整本）。

**verbatim 片段（直接可改写进 prompt）**：

> **Critical rule**: This framework outputs **probability + key levels**, not direction predictions. Use it to **size and structure** trades, not to decide direction. Direction comes from tape + catalysts. Inverting this — letting gamma decide direction — fades dealer hedge flow with retail-style "market structure" interpretation.

> NOT: "stock will hit $X" / INSTEAD: probability + levels + triggers + invalidations + structure recommendation
> ```
> Direction probability: up 65% / down 25% / range 10%
> Key levels:
>   - Breakout trigger: $108 (call wall + zero gamma confluence)
>   - Drawdown invalidation: $103 (put wall break)
> Trigger conditions (ALL must hold): Break $108 with volume > 1.5× 5D avg; sector cohort not down >1%; VIX not above 22
> ```

> **Hard rule of this file — pricing before forecasting.** Never call a macro outcome bullish or bearish before stating what the market already implies. No gap, no trade.

> `margin = (E_low − S) ÷ ATR` — < 0.25 **unexecutable**；≥ 0.5 workable。"the most attractive entry is usually the event-day low, and the event-day low is also the natural invalidation."

**垃圾/不要抄**：`log.md`（198 行 changelog，纯维护噪音）；`OKF.md` 那套 frontmatter 规范对我们没有价值（我们不做知识图谱分发）；
README 里的 marketplace/安装说明；SKILL.md 的 `description` 字段塞了几百字触发词——那是 skill 路由 hack，不是 prompt 质量。
另外 36 条 pitfalls 里有相当比例是同一件事的不同措辞（30/31/34 都在讲 sizing 与 stop），全量灌进 context 是浪费。

## 5. Prompt 重写的 10 条建议（按价值排序）

1. **强制"上一期 mark-to-market"作为第一节**。option-wizard 每天开头必须重报昨天每条建议的实际收盘价与盈亏，用真实数据算，不许自述。Frank 这一节是叙事，我们把它做成**可核对的**才有价值 —— 这也直接对上 helium 的"persist everything"要求。
2. **每条建议必须携带四元组：入场触发 / 加仓线 / 失效价 / 目标**。markout 显示他的 alpha 几乎全在这里（EWZ 条件触发赚 4%，AMZN 270 止损把亏损封在 3.9%）。没有失效价的建议直接不输出。
3. **落地"pricing before forecasting"闸门**：任何方向性表述前必须先陈述市场已隐含什么（IV、加息概率、forward skew、隐含周度 straddle 点数），并量化 gap。无 gap 则输出 "no trade"。
4. **GEX 一节机械化成固定字段表**：spot / HVL / 0DTE HVL / Call Resistance / Put Support / Total GEX / DEX / 1D change / 1D Min-Max，然后"站上 X = A，跌破 Y = B"。这是 Frank 全文最可复制、最不含幻觉的一节，UW 的 `get_gex_levels` + `get_greek_exposure_by_strike` 可直接喂。
5. **禁止 GEX 定方向**（借 trade-skills 原文），GEX 只产出概率+价位；方向来自 tape + catalyst。
6. **加入"利好落地反而下跌 = 定价权耗尽"检测**：对当日 beat-and-raise 却收跌的名字做自动标记，这是 Frank 最可复用的一条启发式，而且完全可由数据计算（earnings surprise × 次日收益率）。
7. **catalyst 预案写成"证实/证伪组合"而非预测**：对每个未来 24–72h 事件，输出"若 A 与 B 同向 → 加仓；若 A 对 B 背离 → 降敞口"。禁止输出单点预测。
8. **情景 A/B/C/D + 显式 base case + 选择理由**，每条情景要写**传导顺序**（先动什么、后动什么）。这是他最有质感的一节，且强迫模型暴露推理链，便于事后打分。
9. **相对/分化优先于绝对方向**：markout 显示他的 pair / 分化判断（IGV vs SOXX、MRVL 空、IWM 空、久期敏感度排序 XBI>IWM>CRWV）明显比 mega-cap 多头准。prompt 里把"今天最大的分化是什么"设为必答项，把"指数会涨会跌"降权。
10. **pitfalls 按情境懒加载，不全量注入**：抄 trade-skills 的反查索引形式，把我们自己的规则做成 `situation → 1–3 条规则` 的映射，配合 helium doctrine 第 4 点（context/token sense 内建）控制每步 context。补充：入场区与止损的 `(E_low − S)/ATR ≥ 0.5` 几何检查，作为输出前的最后一道 lint。
